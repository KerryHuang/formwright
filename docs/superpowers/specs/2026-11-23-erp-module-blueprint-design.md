# ERP 模組藍圖：對照開源 ERP 的完整範圍

2026-11-23。目的：以 ERPNext、Odoo 社群版、Dolibarr、iDempiere 為參照，盤點 Formwright ERP 長期要有的模組與功能，逐領域歸類為第一版、第二版候選、範本套件或不做，並標出哪些只靠現有核心設定就做得出來。結果寫進[功能總清單](../../feature.md)與[路線](../../roadmap.md)；本文件記依據與裁決，不維護段狀態。

## 1. 範圍與做法

- **範圍（使用者裁決 2026-11-23）：** feature.md 做「第一版＋長期藍圖」，每個領域都要有歸類；roadmap 只排第一版。第二版候選在 feature.md 標 💡、說明以「第二版候選」開頭。
- **做法（主控判斷）：** 沿用 feature.md 現有章節，逐項補入，不依應用程式全面重組。理由：重組會讓既有段號、站內連結全部變動，換來的只是閱讀順序。
- **歸類基準：** 沿用路線設計「內建應用程式的取捨基準」（使用者 2026-11-17 裁決）：新增正式應用程式要同時符合跨產業常用、逼出核心還缺的能力；只是常用、核心已能表達的做範本套件。

## 2. 參照系統（2026-11 查證）

| 系統 | 版本 | 判別依據 |
|---|---|---|
| ERPNext | v15.126、v16.60；Frappe HR v16.60 | GitHub 模組目錄；HR、Helpdesk 是另裝的官方 app |
| Odoo 社群版 | 19.0 | 公開 repo 的 addons 目錄（企業版 app 不在公開 repo） |
| Dolibarr | 24.0.3 | `htdocs/core/modules/mod*.class.php` |
| iDempiere | 13 | 官網與 wiki；製造、薪資是外掛 |

四套的最小共同核心是：往來對象、品項、報價到訂單到發票、採購到收貨、庫存、基本會計與銀行、專案。HR、製造、客服是第二層。Odoo 社群版只有開票，完整會計、薪資、簽核、品質、客服、訂閱都在企業版。ERPNext、Dolibarr 的功能細項由模組名稱歸納，未逐頁查證。

## 3. 模組藍圖

### 3.1 正式應用程式（八個）

| 應用程式 | 第一版 | 第二版候選 |
|---|---|---|
| CRM 與銷售 | 潛在客戶、商機、報價、訂單、互動、行銷活動（已上線） | 電子報、問卷、活動對外報名（§4 題 10） |
| 進銷存 | 採購、進貨、出貨、盤點；s2g 單位換算、退貨、預留、批號；s4p 請購、安全庫存 | 供應商詢價、序號、品項變體 |
| MES 生產製造 | 工令、報工、設備；mg1 通用化；s4p 多層 BOM、簡化 MRP | 委外加工 |
| 會計 | 科目、稅別參照、銷項與進項發票、收付款、銀行帳戶與手動對帳、傳票、帳齡、損益表、試算表、折讓 | 對帳單匯入比對、預算對實際、電子發票 MIG 匯出、401 申報檔匯出 |
| 合約與週期開票 | 合約、依週期開發票或訂單 | — |
| HRM | 員工、請假與假別餘額、出勤、費用報支、依部門的資料範圍 | 招募、考核 |
| 專案與工時 | 專案、里程碑、工時、依工時開票 | — |
| 客服與 IT 工單 | 工單類型（客服、IT、維修、到府）、處理人、工時、用料；開進銷存時用料扣庫存 | 依工單開票、知識庫、客戶自行提交（隨對外存取） |

### 3.2 範本套件

品質檢驗、設備保養、預約（已列）；新增固定資產登記。車隊不另做範本，由設備保養範本涵蓋（§4 題 12）。範本套件的開啟機制目前沒有工作段，新排 tp1（§6）。

### 3.3 核心平台新增

- 第一版：稅別共用主檔（tx1）、參照挑選器依上層欄位過濾（rf1）、範本套件開啟機制（tp1）。
- 第二版候選：對外存取（匿名表單＋外部使用者；問卷、報名、客戶入口、客戶提交工單、自助預約共用）、記錄觸發寄信與大量寄送（電子報）、格式化文字欄位（知識庫）。

## 5. 只靠設定做得出來的盤點

依據：`backend/apps/app.schema.json`、五個內建套件、Domain 的事件、檢查、分錄、轉換、報表、任務規則定義（2026-11-23 唯讀盤點）。

**核心現在能表達的：** 21 種欄位型別（含參照、彙總、公式、自動編號、附件、使用者）；表頭加一層明細與條件彙總；參照帶值與目標狀態限定；五種規則（只比對同一筆）；狀態機；含明細的部分轉換；新增、修改、轉移觸發的 create、update、reverse 效果；同模組依組鍵的跨記錄檢查；不可修改分錄與沖銷；簽核流程圖；四種觸發的任務規則（到期日以天計）；單主模組加一子模組的報表；列印範本、儀表板、匯出入；七種權限動作與本人、同群組、全部三層資料範圍；共用主檔、貢獻欄位、整合事件。

**核心目前沒有的：** 對外匿名存取、記錄觸發寄信、自訂週期排程、格式化文字、參照挑選器依本單其他欄位過濾、多來源報表與「相對今天」的區間分桶、以小時計的到期。

### 5.1 純設定（不必等排段）

品質檢驗範本、稅別主檔、會計科目、固定資產登記、銀行帳戶與手動對帳、活動報名（內部登錄）、招募（內部）、供應商詢價、員工主檔雛形、任務內建報表（kr3）。傳票的借貸平衡用跨記錄檢查應做得出來，但草稿階段能否豁免未確認，s3c 先寫驗收測試確認。

### 5.2 大部分設定、缺小能力

| 項目 | 缺口 |
|---|---|
| 多送貨地址、批號挑選、維修單選客戶設備 | 參照挑選器依上層欄位過濾（rf1） |
| 請購單 | 依供應商分組拆單（s4p） |
| 庫存預留、銷退採退、銷項與進項發票 | 履約量與明細追溯（s2e-a） |
| 應收帳齡 | 相對今天的區間分桶 |
| 預算對實際 | 多來源報表（變通：單據參照預算列） |
| 請假與假別餘額 | 工作日與假日曆計算、每年自動給假（週期，ct1） |
| 費用報支 | 明細附件（💡 已列） |
| 客服工單 | 以小時計的 SLA |
| 委外加工 | 依 BOM 帶料（s4p） |
| 知識庫 | 格式化文字與內嵌圖片 |

### 5.3 需核心開發

週期性自動產生單據（ct1）、依欄位分組拆單與多層 BOM、MRP（s4p）、履約量與追溯（s2e）、期間鎖定與報表列結構（s3b）、多幣別（s2h）、依部門或主管的資料範圍（HRM）、時段衝突（階段 5）、參照任務欄位、看板與日曆、記錄觸發寄信、對外存取。

**補了解鎖最多的五個缺口：** ct1 週期產生、s2e-a 履約與追溯、HRM 部門資料範圍、rf1 參照挑選器依上層過濾、階段 5 時段衝突。其中 rf1 原本沒有列，是小能力，所以新排一段。

## 6. 新增工作段（主控判斷位置，待使用者確認）

- **rf1 參照挑選器依上層欄位過濾：** 參照欄位可宣告「依本單另一個參照欄位過濾候選」（例如送貨地址只列本單客戶的、批號只列本單品項的）。排在 s2d-2 之前，s2d-2 的多送貨地址直接用；s2g 批號、客服工單選設備也用得上（鐵則 3：至少兩個不相干的應用程式）。
- **tx1 稅別共用主檔：** 稅別主檔（名稱、稅率、應稅／零稅率／免稅、含稅或未稅、銷項或進項），CRM、MES、進銷存的報價、訂單、採購單改參照稅別並在成立時固定稅率，三個套件升版。排在 s2d-2 之後（同屬共用主檔、一起升版可減少客戶套件更新次數），s3c 硬前置。出廠可帶 5% 應稅一筆當預設值，客戶自己改；不做法定費率表與自動更新。
- **tp1 範本套件開啟機制：** 範本套件與正式應用程式的差別（少量模組、開啟後屬於客戶、不參與整合與升級）及開啟流程。排在 tx1 之後；之後純設定的範本（品質檢驗、固定資產登記）不必等其他段即可上線，設備保養、預約仍等 ct1 與時段衝突。

4. feature.md 的「單位換算」原列在會計一節，移到進銷存。
5. 資料模型 §3.6 客服工單補下游（用料經整合扣庫存）。

## 8. ERP 對照

本文件本身就是對照：§2 列四套參照系統，§3、§4 逐領域對照並寫出簡化理由。和一般 ERP 主要的簡化：不做多公司、POS、官網電商、計薪、折舊、存貨計價（已在「決定不做」）；車輛、固定資產與設備共用一份主檔，不像 Odoo 分成 Fleet、Assets、Maintenance 三個 app；客服工單把 Odoo 的 Helpdesk、Repairs 與 Dolibarr 的 Interventions 合成一個應用程式。
