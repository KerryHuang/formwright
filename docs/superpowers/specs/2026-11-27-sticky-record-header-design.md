# 單據頁標題列固定（詳情頁與表單頁）

## 目的

詳情頁頂部目前疊了三列：「← 模組名」、紀錄標題加列印／編輯／刪除、轉換按鈕（如「轉成進貨單」），約 190px 高。單據長了往下捲，動作按鈕就捲走，要捲回頂端才能編輯或列印。表單頁一樣：手機寬度「取消」在最上面、「儲存」在兩千多 px 長頁的最底下。

使用者裁決（2026-11-27）：

1. 詳情頁的返回、標題、狀態與全部動作併成一列，捲動時固定在頁首下方。
2. 手機寬度（390）改成頂部固定標題列，加上底部固定動作列；次要動作收進「更多」。
3. 詳情頁與表單頁一起改，兩頁長相一致。

來源：2026-11-27 全站 UI／UX 審查（本機 `.tmp/20261127-uiux-review/report.md` 的 P13、P14），以及使用者截圖。

## 範圍

- 動態詳情頁 `frontend/src/pages/dynamic/DetailPage.vue`。
- 動態表單頁 `frontend/src/pages/dynamic/FormPage.vue`（新增與編輯）。
- 不含系統管理頁、設計器、報表；不改後端。

## 行為

### 寬版（≥ 600px，Quasar `sm` 以上）

詳情頁標題列一列排完：

```text
┌───────────────────────────────────────────────────────────────────┐
│ ← 採購單 / PO-202611-0004 [簽核章]    [送簽…][轉成進貨單][列印▾][編輯][刪除] │
└───────────────────────────────────────────────────────────────────┘
```

- 左側：返回鈕（圖示＋模組名，連回列表，沿用 `dynamic.backTo` 無障礙名稱）、分隔「/」、紀錄標題（沒有標題欄位的模組不顯示標題，只留返回鈕），以及既有的簽核章 `ApprovalBadge`。
- 右側：送簽按鈕（每個可送的目標一顆）、轉換按鈕（每個允許的轉換一顆）、列印選單、編輯、刪除。出現條件與現在完全相同（`canEdit`、`canDelete`、`submitTargets`、`c.allowed`、有列印範本），本設計只搬位置。
- 捲動時整列 `position: sticky` 固定在頁首（`q-header`）正下方，有底色與下邊框，不透出底下內容；頁首高度變化（換行、縮放）時固定位置跟著變。
- 寬度不夠一列時，右側動作整組換到第二列（仍在固定列內），不擠壓標題；標題過長照現在的 `overflow-wrap: anywhere` 換行。
- 轉換的「不能轉的原因」與「已轉出的單據」連結留在原位（內容區上方），不搬進標題列。

表單頁同一個元件：

```text
┌───────────────────────────────────────────────────────────────┐
│ ← 採購單 / 編輯採購單                                     [取消][儲存] │
└───────────────────────────────────────────────────────────────┘
```

- 左側：返回鈕（新增時連回列表、編輯時連回該筆詳情，與現在的 `back()` 相同）、標題沿用 `dynamic.newOf`／`dynamic.editOf`。
- 右側：「取消」（flat，行為同現在）與「儲存」（primary）。儲存送出的是同一份表單（用原生 `form` 屬性或等效做法），驗證、`saving` 轉圈、`canSave` 條件全部沿用 `DynamicForm` 現有邏輯；表單底部原本的儲存鈕移除，不留兩顆。
- 簽核進行中（`approvalPending`）時沒有儲存鈕，只有返回。

### 手機（< 600px）

```text
┌────────────────────────────┐
│ ← PO-202611-0004 [簽核章]   │ ← 頂部固定
│ …內容…                     │
├────────────────────────────┤
│ [編輯]             [更多 ▾] │ ← 底部固定
└────────────────────────────┘
```

- 頂部固定列：返回鈕只顯示圖示（無障礙名稱仍是「回到〈模組〉」），加紀錄標題與簽核章；沒有標題時顯示模組名。
- 底部固定動作列（沿用 `ApprovalActionBar` 的 `QPageSticky position="bottom" expand` 做法與 safe-area 內距）：
  - 主要動作一顆：詳情頁有「編輯」就是編輯；沒有編輯但有送簽目標時是第一個送簽目標；兩者都沒有就不放主要動作。
  - 其餘動作（其他送簽目標、轉換、各列印範本、刪除）收進「更多」選單；刪除放最後、標紅，點了仍開原本的確認對話框。
  - 選單內每個列印範本一項，文字「列印：〈範本名〉」；轉換一項一個目標，文字沿用 `docflow.convert.button`。
  - 一個動作都沒有就不顯示底部列。
- 表單頁手機：頂部固定列放返回圖示＋標題；底部固定列放「取消」與「儲存」（儲存在右、primary），沒有「更多」。
- 內容區底部留出動作列高度，最後一塊不被蓋住（沿用 `barPad` 的做法）。

### 與手機簽核動作列並存

手機詳情頁在使用者有簽核動作時已經有底部固定的 `ApprovalActionBar`（核准、退回等）。兩條不疊加：

- 簽核動作列出現時，紀錄動作不另開底部列，改成頂部固定列右側一顆「更多」選單（同一份項目清單，含編輯）。
- 簽核動作列不出現時，照上一節顯示紀錄動作底部列。

### 選單與對話框

「更多」選單關閉時內容會卸載，因此列印預覽、轉換對話框、刪除確認、送簽對話框都不能放在選單裡；選單項目只負責觸發，對話框放在頁面層（或選單外常駐的元件）。

## 不變的事

- 所有動作的出現條件、權限判斷、對話框與 API 呼叫不變；這次只改位置與排版。
- 不新增任何業務政策或寫死的模組判斷（鐵則 1、2）；動作清單完全由 schema、權限與 API 回傳決定。
- 測試鉤子（`data-testid`）沿用既有名稱；新元件新增的鉤子自取，不改舊的。

## 介面與實作邊界

- 新增共用元件（建議 `frontend/src/presentation/dynamic/components/RecordHeaderBar.vue`）：負責返回、標題、徽章插槽、動作插槽、sticky 與手機底部列；詳情頁與表單頁共用。
- 頁首高度：在 `MainLayout.vue` 的 `q-header` 內放 `q-resize-observer`，把高度寫成 CSS 變數（如 `--app-header-h`）給 sticky 的 `top` 用；不寫死 px。
- 列印與轉換要能以「按鈕」與「選單項目」兩種形式觸發同一個對話框；做法（拆出觸發與對話框、或 composable）由實作者決定，維持現有測試通過。
- 介面文字：沿用既有鍵；新增的鍵（如「更多」若沒有現成鍵、「列印：{name}」）四語同時補上，照 `.claude/rules/frontend.md` 的 i18n 規則。
- 主題：底色與邊框用 `--t-panel`、`--t-border` 等 token，八種風格、淺色深色都要正常（`no-hardcoded-colors` 測試會擋寫死的顏色）。

## ERP 對照

ERP 單據畫面的慣例是「單據頭工具列」：單號、狀態與動作（編輯、列印、轉單、作廢）固定在頂部，單身再長也不必捲回去找按鈕，SAP Business One、Odoo 的表單都是這樣。本設計把這個慣例做成所有動態模組共用的平台能力，任何模組（CRM、進銷存、MES 或客戶自建）都自動得到，不為個別單據寫頁面（鐵則 5「不替個別模組手寫頁面」）。

## Demo 資料

不改種子；既有採購單（有轉換、列印、歷程）與訂單足以示範成功路徑，唯讀角色帳號示範「沒有動作」的分支，待簽核單示範與簽核動作列並存。

`docs/manual.md` 記錄詳情頁一節補一句：動作按鈕固定在標題列，手機在底部，次要動作在「更多」。
