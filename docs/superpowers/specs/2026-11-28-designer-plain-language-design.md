## 1. 術語白話化（P06）

### 1.1 對照表

| 舊詞 | 新詞 | 說明 |
|---|---|---|
| 狀態機 | 狀態流程 | 票例 |
| 出廠值 | 預設值 | 票例；「恢復出廠值」→「恢復預設值」 |
| 可模組覆寫、模組覆寫、覆寫為 | 各模組可另設、模組另設、另設為 | 只限政策相關字串 |
| 跨記錄驗證、跨記錄檢查 | 存檔檢查 | |
| 分錄（模組類型） | 流水帳 | 「沖銷分錄」→「沖銷紀錄」，「設為分錄模組」→「設為流水帳」 |
| 連動事件 | 自動動作 | |
| 每列代表 | 每一列是 | 報表 |

外語照同一個意思改寫（en-US：State flow／Default／Set per module／Save checks／Log／Automations／Each row is；th、vi 照英文意思譯），四語鍵集合一致。

主控裁決，待使用者確認：除了票上舉的兩例，其餘新詞都是主控選的。選錯的代價是語系檔與手冊要再改一輪。

### 1.2 範圍與判定

- `shared/i18n/<code>/ui.json` 四語：只改值、不改鍵名。凡是指同一個概念的字串都改，包括積木包更新頁（`apps.upgrade.*`）、稽核（`audit.*`）、維運（`ops.health.*`）、AI 連線說明（`aiAccess.*`）。
- 不改：語系包的「覆寫」（`localePacks.*`，指翻譯覆寫，是另一個概念）；`demoData.conflictHint` 的「覆寫既有資料」（一般動詞）。
- 後端寫死的使用者可見訊息，若有上表舊詞也一起改（grep `backend/src` 的雙引號字串，排除註解與積木包格式驗證器的細部錯誤，理由同 #139 §2.2）。
- `docs/manual.md` 同步改，改到章節標題時一併修錨點連結。

### 1.3 分頁用途說明

模組編輯頁（`ModuleEditorPage.vue`）分頁列下方，顯示目前分頁的一行用途說明（`text-caption` 次要文字色，`data-testid="tab-purpose"`），鍵 `designer.tabPurpose.<分頁名>`，四語：

| 分頁 | 說明（繁中） |
|---|---|
| 欄位 | 這張表單有哪些欄位、怎麼排。 |
| 規則 | 依條件顯示、隱藏、必填或自動計算欄位。 |
| 任務規則 | 單據到某個狀態時，自動指派任務給人。 |
| 政策 | 這個模組要不要用和全系統不同的上限或預設值。 |
| 狀態流程 | 單據有哪些狀態、可以怎麼往下走。 |
| 簽核流程 | 哪些狀態要先經過誰同意。 |
| 自動動作 | 狀態改變或存檔時，自動去改別的資料。 |
| 存檔檢查 | 存檔前檢查和別筆資料有沒有衝突，例如庫存不能變負數。 |
| 流水帳 | 建立後不能改、只能沖銷的紀錄，例如庫存異動。 |
| 列印範本 | 列印或另存 PDF 時的版面。 |
| 權限 | 哪些群組能看、能改這個模組。 |
| 預覽 | 用一般使用者的角度看這張表單。 |

## 2. 圖示盤（P06）

`presentation/dynamic/designer/IconSelect.vue` 改成圖示盤：

- 觸發處是一顆按鈕，顯示目前圖示與標籤「圖示」，不顯示代碼。
- 點了開 `q-menu`（手機 `q-dialog`），裡面是 `MODULE_ICONS` 的格線（每格 40×40 以上可點區域），目前選中的有主色外框；點一格就選定並關閉。
- 每格 `aria-label` 與 tooltip 用白話名稱，鍵 `designer.icons.<圖示代碼>`，四語（例如 `local_shipping` →「貨車」、`receipt_long` →「單據」）。
- 不再提供文字搜尋（24 個圖示一眼看得完）。
- 既有 `IconSelect` 的使用處都換成新樣子；`MODULE_ICONS` 清單與第一個是預設值的規則不變。
- 舊資料的圖示不在清單內時：按鈕照樣顯示那個圖示，圖示盤裡沒有選中項。

## 3. 進階：顯示代碼（P06）

- 設計器（模組清單頁 `ModuleListPage.vue`、模組編輯頁）頁首加一個開關「顯示代碼」（`q-toggle`，`data-testid="show-codes"`），預設關。開關狀態存 localStorage（鍵 `formwright:designer-show-codes:<userId>`，壞資料或無法存取當關），兩頁共用同一個值。
- 關的時候隱藏：
  - 模組清單的「程式代碼」欄（`programCode`）與模組代碼（若有顯示）。
  - 模組編輯頁欄位清單每列的欄位代碼（`ModuleEditorPage.vue:380` 的 `· {{ f.key }}`），只留型別。
  - 簽核流程卡片上的流程代碼（`ApprovalFlowsTab.vue` 的 `{{ f.key }}`）。
  - 實作時 grep 設計器內其他直接顯示 `key`、`code`、`programCode` 的地方，一併納入，交付說明列出。
- 開的時候照現在顯示。
- 新增、編輯對話框裡**必填的代碼輸入欄**（例如新增模組的代碼）不受這個開關影響，照常顯示（不填不能存）。欄位編輯對話框裡唯讀顯示的代碼收進對話框底部的「進階」`q-expansion-item`。

## 4. 模組設定收起（P05、P23）

- 模組編輯頁目前排在分頁前的 6 個設定（圖示、記錄標題欄位、啟用任務、選單分區、其他語系、標題樣板）包進一個 `q-expansion-item`「模組設定」，**預設收起**（`data-testid="module-settings"`）。收起時標題列右側摘要顯示目前圖示與選單分區名稱。
- 展開與否不記憶，每次進頁都收起。
- 結果：1366 寬度下分頁列頂端在視窗 y ≤ 220px；390 寬度下 y ≤ 360px。
- 分頁列（P23）：`q-tabs` 加 `outside-arrows mobile-arrows`，箭頭不蓋住分頁名；「標題樣板」輸入框在 390 寬度不貼右緣（容器加內距或改 `col-12`）。

## 5. 政策設定頁（P18）

`pages/system/PoliciesPage.vue`：

- **依分類分頁**：分類（`groupByCategory` 的結果）改成 `q-tabs`（≥ 1024 寬度放左側垂直分頁，以下放上方可捲動的水平分頁），一次只顯示一個分類。預設第一個分類；網址帶 `?category=<分類>` 可直接開到那一類（重新整理不跳回第一類）。
- **一組一個儲存**：每個分類底部一個「儲存」按鈕（`data-testid="policy-save-<分類>"`），一次存該分類內所有改過的項目；沒有改過時停用。每列原本的儲存按鈕拿掉；「恢復預設值」保留在每列，按下只改草稿，要按分類的儲存才生效。
- **存檔流程**：照順序逐項呼叫現有的單項 API（不新增後端批次 API）。營運時區、雙因素自鎖的確認對話框照舊，在送出那一項之前跳出；按取消就停在那一項，前面已存的保留、後面的不送。某一項失敗時錯誤顯示在那一列，其餘照送；全部完成後一則通知：全成功「已儲存 N 項」，有失敗「已儲存 N 項，M 項失敗」。
- **切分類時有未存的改動**：跳確認「這一類有改動還沒儲存，要放棄嗎？」，取消就留在原分類。
- **每列只說一次**：名稱一次、說明一次，下面一行「目前值：…／預設值：…」（有範圍才加「／範圍：…」）。「各模組可另設」章保留。
- Demo 站帳號安全分類的唯讀規則（`readonlyRow`）照舊：唯讀分類不顯示儲存按鈕。

## 6. 簽核流程列表（P20）

`presentation/dynamic/approval-designer/ApprovalFlowsTab.vue`：

- **只留一個新增**：保留頁首的「新增流程」（`flow-add`，在對話框裡選目標狀態），拿掉每組的「在這組新增」（`flow-add-<狀態>`）。某組沒有流程時，該組顯示「還沒有流程」文字即可。
- **鎖頭附文字**：被使用、不能刪除的流程，鎖頭旁加文字「使用中，不能刪除」（`text-caption` 次要文字色）。
- **狀態只用一種表達**：拿掉「停用中」章（`flow-inactive-<key>`），只留啟用開關，開關旁標籤寫「啟用」；停用的卡片維持現有的淡化樣式。
- 列內純圖示按鈕（編輯、上移、下移、刪除）保留圖示，但每顆加 tooltip（同 `aria-label` 文字）。

## ERP 對照

用詞對照 ERP 常見說法：狀態流程對應 Odoo 的 stage／SAP 的 status profile；流水帳對應 ERP 的 ledger（不可修改、只能沖銷）；存檔檢查對應 SAP 的 validation。本票不新增主檔或單據。

## 宗旨檢查（2026-11-28）

1. 機制還是政策：通過。只改文字與呈現；政策的值與範圍照舊由系統管理員設定。
2. 寫死掃描：設計階段不適用。可寫死清單：圖示清單 `MODULE_ICONS`（既有）。
3. 單一來源：通過。政策的預設值與範圍仍只從 API 取得。
4. 兩個應用程式：不適用。
5. 空系統：通過。沒有模組時設計器清單照常，政策頁不依賴任何積木包。
6. 套件只用定義組成：不適用。
7. ERP 對照：見上一節。
8. 權限與驗證：通過。政策儲存仍逐項經後端驗證；唯讀分類照舊。
9. 不限產業：通過。分頁說明的例子（庫存）是通用的。

## 驗收

### AC-01 術語白話 [ui]
#### 步驟
1. 以系統管理員 Demo 帳號登入，開一個有狀態流程的模組（例如進銷存採購單）的編輯頁，看分頁列。
2. 開系統政策頁。
#### 預期
- 分頁名是「狀態流程」「自動動作」「存檔檢查」「流水帳」，看不到「狀態機」「連動事件」「跨記錄驗證」「分錄」。
- 每次切分頁，分頁列下方都有一行這個分頁的用途說明。
- 政策頁寫「預設值」「各模組可另設」，看不到「出廠值」「覆寫」。

### AC-02 外語同步 [ui]
#### 步驟
1. 切換到 English，看模組編輯頁分頁列與政策頁。
#### 預期
- 分頁名是 State flow、Automations、Save checks、Log；政策頁寫 Default。
- 四語鍵集合一致（locales spec 通過）。

### AC-03 圖示盤 [ui]
#### 步驟
1. 模組編輯頁展開「模組設定」，點「圖示」，選「貨車」。
#### 預期
- 彈出的是圖示格線，沒有任何圖示代碼文字；滑過或聚焦一格會顯示白話名稱。
- 選了之後按鈕顯示貨車圖示，側欄該模組的圖示同步更新。

### AC-04 顯示代碼開關 [ui]
#### 步驟
1. 開模組清單頁，確認「顯示代碼」是關的；再開一個模組的編輯頁與簽核流程分頁。
2. 打開「顯示代碼」，重新整理頁面。
#### 預期
- 關的時候：模組清單沒有「程式代碼」欄，欄位清單只顯示型別、沒有 `f_` 開頭的代碼，流程卡片沒有流程代碼。
- 打開後三處都顯示代碼；重新整理後仍是打開的；換到另一頁也是打開的。

### AC-05 模組設定預設收起 [ui]
#### 步驟
1. 1366 與 390 寬度各開一個模組編輯頁。
#### 預期
- 「模組設定」是收起的，摘要看得到目前圖示與選單分區。
- 分頁列頂端：1366 在 y ≤ 220px，390 在 y ≤ 360px；第一屏看得到欄位清單。
- 390 寬度分頁列箭頭不蓋住分頁名。

### AC-06 政策依分類分頁 [ui]
#### 步驟
1. 開政策頁，點第二個分類，重新整理。
#### 預期
- 一次只顯示一個分類；重新整理後仍在第二個分類（網址帶 `category`）。
- 每列名稱、說明各出現一次，下面一行「目前值／預設值」。
- 每列沒有自己的儲存按鈕，分類底部一個「儲存」，沒改動時是停用的。

### AC-07 政策分組儲存 [ui]
#### 步驟
1. 在同一個分類改兩項，其中一項填超出範圍的值，按分類的「儲存」。
#### 預期
- 合法的那項存成功，超出範圍的那列顯示錯誤；通知寫「已儲存 1 項，1 項失敗」。
- 修正後再按儲存，通知「已儲存 1 項」。

### AC-08 切分類有未存改動 [ui]
#### 步驟
1. 改一項不存，點另一個分類。
#### 預期
- 跳出「這一類有改動還沒儲存，要放棄嗎？」；取消就留在原分類、改動還在。

### AC-09 政策確認對話框照舊 [ui]
#### 步驟
1. 在地區分類改營運時區，按儲存，在確認對話框按取消。
#### 預期
- 營運時區沒有存；同一批排在它後面的項目也沒有送出。

### AC-10 簽核流程列表 [ui]
#### 步驟
1. 開一個有簽核流程的模組（例如進銷存採購單）的簽核流程分頁。
#### 預期
- 整頁只有一個「新增流程」按鈕。
- 使用中的流程鎖頭旁有「使用中，不能刪除」。
- 停用的流程只看得到關著的開關與淡化卡片，沒有「停用中」章。
- 滑過編輯、上移、下移圖示會顯示文字提示。

### AC-11 四寬度與深淺色 [ui]
#### 步驟
1. 模組清單、模組編輯頁、政策頁、簽核流程分頁，在 390、820、1366、1920 四種寬度與淺色、深色主題各看一次並截圖。
#### 預期
- 不橫向捲動；圖示盤選中外框在深色主題看得到；說明文字對比 ≥ 4.5:1。
